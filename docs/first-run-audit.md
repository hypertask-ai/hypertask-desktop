## Native regression scenarios

`crates/ht-desktop/src/first_run_tests.rs` uses a real Worker, on-disk empty Db and GPUI windows. Gates hold server responses to observe loading frames. Assertions inspect measured native text and durable SQLite contents, not only transport call counts.

- `fresh_signin_inbox_row_board_card_walkthrough_fetches_real_content`: inbox, first row, task description author/assignee/tag/status/project, comments/draft, board, first card; reject any rendered offline message throughout.
- `never_synced_board_loads_instead_of_blank_and_embeds_uncached_metadata`: initially absent projects/sections/tasks, loading frame, fetched board/card metadata and AI board label.
- `fresh_task_loads_catalog_and_draft_even_when_comments_fail`: independent retry domains, fetched member/tag/section catalogs and restored server draft.
- `fresh_task_waits_for_draft_owner_before_allowing_comment_input`: delay identity, render task content without an unowned composer, reject Ctrl+M until ownership resolves, then restore the server draft.
- `fresh_search_fetches_uncached_result_then_opens_full_task`: empty-cache search, loading, fetched partial result, detail fetch/loading and task AI label.
- `fresh_command_search_fetches_and_keyboard_opens_uncached_task`: native command search, loading and Enter through the shared task opener.
- `uncached_task_scope_keeps_route_id_without_borrowing_another_board`: cache-independent task identity and no fabricated project ID.
- Existing `opening_uncached_task_fetches_renders_and_caches_server_response`, `failed_uncached_task_request_shows_offline_only_after_failure`, `late_task_response_caches_without_replacing_newer_task` remain required.

The sign-in walkthrough simulates successful authentication by installing a mocked Worker at the same boundary used by `Event::SignedIn`; it does not contact the authentication service. This proves native startup/navigation and server-cache behavior, not live SaaS authorization.
